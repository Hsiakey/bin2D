# 路线图

> 每一阶段都写"开工条件"——没到条件就不做，避免把"想做的功能"当成"现在要做的事"。

## ① 地基（已完成；当前版本 0.1.2 = 地基 + 性能轮 + 分层文档）

交付：`Surface / Image / Transform / Path / Paint / raster / Canvas / Scene / gpu`，
5 套测试 + 1 套可选 GPU 往返测试，演示图 `build-mingw/out/bin2d-demo.png`。

验收（已达成）：`make all` 零警告、`make test` 全绿（94 项断言）、`make layers` 通过、
`make demo` 出图。

## ② 上层 UI 库改吃 bin2d（进行中：填充 ✅ 0.5.0 / 描边 ✅ 0.6.0，下一步圆角/投影）

**目标**：UI 库的路径填充/描边不再自己算条带，改成调 bin2d 的 `Path + raster`；
后端只负责"把最终位图或四边形刷到屏幕"。

**已交付**：0.5.0 导出填充覆盖率（`RasterizeCoverage`）→ binUI 0.21.0 换掉 `<path>` 填充的
扫描线；0.6.0 导出描边覆盖率（`RasterizeStrokeCoverage`，并集取 max）→ binUI 0.22.0 换掉
逐段 `fillLine` + 拐点补片。两处都是"宿主的条带管线不动，只把覆盖率来源换成 bin2d"。

**迁移顺序**（每步都要能单独回滚）：

1. ~~**条带数学 → 路径光栅**：`<path>` 的扫描线条带换成 bin2d 的覆盖率。~~ ✅（0.5.0 / 0.6.0）
2. **圆角/投影**：`fillRounded`、假投影（半透明叠层）换成 bin2d 的圆角路径与 `Shadow`。
3. **图层**：UI 现有的 `pushLayer/popLayer` 语义（离屏 + 组透明度）与 bin2d 的 Canvas
   图层栈对齐，后端里的三份离屏实现可以退休。
4. **明确不迁移**：文本（字形图集是 UI 库自己的事）、窗口/事件/布局（bin2d 不认这些）。

**验收线（硬指标）**：GL / D3D11 / Vulkan 三端像素基准 **0 diff**、8 个示例无回归 ——
每步的"删除条件"和逐文件台账见 [layering.md](layering.md) §4；
一条路径要么走老实现要么走新实现，不允许"两边都画一半"。

**开工条件**：bin2d 的 `raster` 在 UI 的最大节点（800×600 卡片 + 200 个图元）上
单帧耗时 ≤ 现实现 × 1.2。达不到就先优化扫描线（见 ④ 的前两项），别把性能问题带进 UI。

**开工条件已达标（2026-11-18，binUI `make gate-migrate`）**：0.4.1 实测 1.61× ❌ →
0.4.2 实测 **0.98×** ✅（B 15.03 → 9.22 ms；同口径，同一份设备空间折线 + 同一块内存
Surface + 都含清屏）。做法是"整像素段的覆盖率累加改成差分 + 行尾前缀和"，
**像素值与 0.4.1 逐项相同**（`make quality` 七项数字不变）。数字与归因见
[perf.md](perf.md) 的「迁移开工条件那一轮」。

> 仍未做（开放项，不阻塞迁移）：把每行的 8 条子扫描线换成"行首/行尾两次求交 +
> 梯形解析面积"。它能再快 ~2×、AA 也更精确（竖直 1/8 量化消失），但会**改像素值**，
> 属于新语义，所以要单独一轮 + 单独验收，不能混在性能轮里。

## ③ GPU 路径：合成交给 binGPU —— **已落地（0.3.0）**

**目标**：图层合成、大图重采样走 GPU；软件路径保留为"没有驱动时的底线"。

**交付**：`GpuCompositor`（`include/bin2d/gpu.h`），三项欠账全部补齐：

- **多图层批量合成** ✅ 一个回合合成 N 层（一次 `frame_begin/frame_end` + 一次回读），
  相邻图层按"纹理 + 混合模式 + 采样器"合批（8 层同纹理 → `draws == 1`）；
- **纹理池** ✅ 按 (宽,高,用途) 分桶复用 + `upload(box)` 脏矩形上传；
- **五种混合模式全量对齐** ✅ 4 个后端（CPU / VK / D3D11 / GL）各跑一遍五模式多图层场景，
  与 CPU 的 `DrawSurface` 逐像素最大通道差 **1**，且四端**彼此完全相同**。

另加两件不在原计划里的东西：

- **离屏渲染目标**（`acquireTarget/composeTo/readTarget`）：图层套图层不落 CPU 内存；
- **合成基准**（`make bench-gpu`）：CPU / GPU 每帧上传 / GPU 纹理常驻 三条路线对比。

**开工条件的裁决**（原文："出现每帧合成 ≥ 8 个图层或视口 ≥ 1280×720，且 CPU 合成占帧
时间 > 40%"）：数字满足 —— 1280×720×16 层 CPU 合成 **11.1 ms**，在 16.7 ms 的帧预算里
占 66%。但**结论分两半**（详见 [perf.md](perf.md)）：

- bin2d 自己的 `Surface → Surface` 接口**不适合**改走 GPU 默认路径：每帧回读就要
  5.7–10.5 ms，是合成本身（0.2 ms）的 30–60 倍，净收益接近零甚至为负；
- 一旦消费者不要求 CPU 侧像素（合成结果留在显存接下一层、或直接在窗口里呈现），
  合成只要 **0.17–0.21 ms**，是 CPU 的 **53–67 倍** —— 这是上层 UI 库的形态，不是 bin2d 的。

所以本阶段的产物是：**语义完备、可逐像素验收、可被上层直接调用的合成器**，
默认路径仍是 CPU；GPU 由调用方按场景点名（`composeTo` 那条才是性能入口）。

**顺带修掉的 CPU bug**（不修就没法对齐）：`DrawSurface` 的两条快路径无视 `RasterTarget::blend`、
`a==0` 的源像素在 `Replace/Keep` 下被错误跳过、`nearest` 在轴对齐路径失効。

## ④ 滤镜 / 投影 / 九宫格 / mip

> **0.4.0 已交付 mip 这一项的一半**：缩小的盒式预滤波（`Image::sampleSurface`）。
> 8× 缩小与理想盒式平均的偏差 31.8 → **0.0 级**；代价是 2 的幂分级、不做各向异性。
> 剩下的（大图斜看时的各向异性、mip 的显存上限控制）等真出现"大面积旋转贴图"再说。

- **滤镜**：模糊已有（盒式 ×2）；要补灰度/色相/亮度对比度。
- **投影**：现在是"画形状 → 模糊 → 贴回"三步；要支持"投影只对 alpha 通道"以省一半内存。
- **九宫格**：已有；缺"按目标尺寸自动选九宫格边界"（从图里探测边）。
- **mip**：✅ 0.4.0 已做（盒式预滤波，见本节开头）。

**开工条件**：UI 侧真出现"需要滤镜/大图缩放"的界面；这条不阻塞 ②。

## ⑤ 缓存与脏区

`Scene` 现在**故意**不做缓存：先把"渲染结果 == Canvas 直接画"这条基线钉死。

- **版本号驱动**：`Scene::version()` 已存在。下一阶段是"每个节点带自己的 version，
  父节点缓存子树位图，version 没变就直接贴"。
- **脏区**：记录上一帧的脏矩形，只重画脏区内的节点。
- **量化**：缓存一张 660×470 的位图是 1.2 MB，缓存的粒度要按"图层"而不是"节点"，
  否则内存爆炸。

**开工条件**：出现"静态内容占比 > 70% 且帧率不足"的场景（设置页/侧栏这类）。
届时先做 ②，因为 ② 之后节点树还在 UI 那边，缓存放在 bin2d 里才自然。

## 明确不做

- **文本排版**：字形图集、bidi、行高归上层库；bin2d 只画它给的位图。
- **布局/事件/窗口**：bin2d 不认"节点盒"、不认鼠标。
- **3D**：那是 bin3d（横向用 bin2d 画 2D 覆盖层）。
- **动画/时间轴**：调用方每帧改 transform/paint 再重画即可。
